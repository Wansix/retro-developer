# 《옛날 개발자》 개발 단계

## 추가 기획판 실행

2006년 3월 6일 월요일에 시작한다. 평일 09시에 출근하고 12시부터 한 시간 동안 점심시간을 보낸 뒤 18시에 퇴근이나 야근을 선택한다. 토요일은 09시부터 12시까지 근무하고, 일요일은 쉰다. 토요일을 포함한 10근무일 안에 업무 16건과 인사평가 270점을 달성하고 배포 검수를 통과해야 한다. 남은 추가 일감도 0건이어야 한다. 결산에 표시되는 코딩·회의·협상 시간은 게임 내 업무 시간이다.

Node.js 22 이상을 사용한다. 저장소 루트에서 로컬 D1 마이그레이션을 적용한 뒤 Pages를 실행한다.

```sh
mkdir -p .wrangler/public
cp index.html .wrangler/public/
cp -R src .wrangler/public/
npx --yes wrangler@4.168.0 d1 migrations apply RETRO_DB --local --config wrangler.local.jsonc
npx --yes wrangler@4.168.0 pages dev .wrangler/public \
  --d1 RETRO_DB=a05fa4aa-61de-45c2-b4ac-a90b910e7f4d \
  --compatibility-date 2026-11-25 --compatibility-flag nodejs_compat
```

브라우저에서 [로컬 게임](http://localhost:8788)을 연다. Python은 Pyodide, JavaScript는 QuickJS, C++은 Clang과 WASI를 별도 브라우저 워커에서 사용한다. 첫 실행 때 런타임 파일을 CDN에서 받으며 작성한 코드는 브라우저에서 실행한다. `node --test tests/*.test.mjs`로 업무 배분과 채점 데이터, 결산 재생을 확인할 수 있다.

운영 프로젝트 `retro-developer`는 Cloudflare Pages 직접 업로드를 사용한다. `main`을 푸시한 뒤 위 예시와 같이 `index.html`과 `src/`를 정적 출력 디렉터리에 복사하고, 저장소 루트에서 다음 명령으로 같은 커밋을 배포한다. 운영 Pages Functions는 `RETRO_DB`로 운영 D1에 연결한다. 새 마이그레이션이 있으면 배포 전에 운영 D1에 적용한다.

```sh
npx --yes wrangler@4.168.0 pages deploy .wrangler/public \
  --project-name retro-developer --branch main --commit-hash "$(git rev-parse HEAD)"
```

로그인한 계정은 종료 시 결산을 자동 저장한다. 로그인 전에 끝낸 회차는 기록실에서 로그인한 뒤 저장할 수 있다. 서버는 선택 이력을 재생해 결산을 계산하고, 브라우저의 언어별 실행기와 에디터가 코딩 검수와 복붙 이벤트를 판정한다. 게임 규칙을 변경할 때는 `RULESET`과 이어 하기 저장 형식을 함께 검토한다.

## 이전 10일 데모 개발 이력

아래는 기존 기획서 §7과 §8을 바탕으로 남긴 개발 이력이다.

## Phase 0 — 프로젝트 기반
- GitHub + Cloudflare Pages 호스팅 세팅 ✅ 완료
- 정적 파일 구조(`index.html`, `src/`), 푸시 시 자동 배포 여부 결정

## Phase 1 — 인트로부터 첫 실행까지
- 승인 반복 인트로 → 시간 이동 → 2006년 사무실
- 레트로 사무실 레이아웃(상태바 / 김 과장·문제 / 에디터+실행 결과)
- 코드 에디터(붙여넣기 차단) + 브라우저 Python 런타임(Pyodide) 워커 실행
- 미션 1 "Hello, World!" 실제 실행 → 출력 → 제출·채점 → 진행 반영
- **완료 조건**: 브라우저에서 첫 문제를 실제 Python 실행으로 풀고 제출까지 된다

## Phase 2 — 코어 게임 루프
- 상태 관리: 날짜(10일), 첼력, 행동력, 프로젝트 진행, 인사평가
- 행동 7종: 직접 해결 / 박 대리 힌트 / 커피 / 아부 / 위임 / 정시 퇴근 / 야근
- 미션 2~6 구현 + 고정 순서 진행
- 채점 고도화: 출력 비교, 검증 케이스, 오류 유형별 메시지
- 복붙 적발 대사 3종, 힌트 단계 공개
- **완료 조건**: §7 MVP 완료 판정의 실행·채점·복붙 항목 통과

## Phase 3 — 평가·엔딩·결과
- 최 사원 비교(일일 인사평가, 정시 퇴근 시 +65)
- 엔딩 5종 판정(우선순위: 병원 → 영원한 신입 → 차기 김 과장 → 골든 키보드 → 평범한 개발자)
- 회차 결과 화면 + 재시작 + 로컬 최고 기록(localStorage)
- **완료 조건**: §7 MVP 완료 판정 전 항목 통과(직접/전부 위임 클리어, 엣지 케이스)

## Phase 3.5 — 반전 엔딩: 김 과장의 정체
- 핵심 반전: 2006년 사무실은 AI가 만든 시뮬레이션이며, 김 과장은 AI 에이전트(KIM_MANAGER)가 연기한 캐릭터.
- 귀환 성공 엔딩(차기 김 과장/골든 키보드/평범한 개발자) 직전에 반전 시퀀스 재생:
  마지막 인사 → 김 과장 정지 + 글리치 → [SIMULATION COMPLETE] 시스템 로그
  (대사 생성 수·추가 업무 수는 실제 플레이 통계 반영) → 주인공·AI 대화 → 업적 달성.
- 엔딩 크레딧: 전 직원 역 AI / 실제 코딩 및 야근 담당: 플레이어
  마지막 문구 "이 게임에서 유일하게 직접 일한 존재는 당신이었습니다."
- 반전은 고정 대사로 유지. 플레이 중에는 김 과장이 AI임을 절대 노출하지 않는다.
- **완료 조건**: 클리어 시 반전 → 크레딧 → 결과 화면 순으로 재생되고 통계가 실제 기록과 일치.

## Phase 3.6 — AI 김 과장 대사 생성 (선택적)
- 상황별 잔소리(오류, 빠른 해결, 과잉 출력, 무한 루프, 정시 퇴근 등)를 LLM으로 생성.
- 구조: 클라이언트 → Pages Function(`/api/boss-line`, API 키는 서버 측 env) → LLM.
- AI는 대사 생성만 담당. 점수·판정·업무 처리량 등 게임 로직은 변경 불가.
- 비용·지연 고려: 일부 상황만 호출, 실패·시간 초과 시 고정 대사로 자연스럽게 대체.
- API 키 미설정 시 MVP는 고정 대사만으로 완전히 플레이 가능.
- **완료 조건**: 키 없이 모든 기능 정상 동작(폴Fallback), 키 설정 시 동적 대사 표시.

## Phase 4 — 밸런스·플레이테스트 (MVP 마무리)
- 초보자 플레이 관찰, 안내 문구 보강
- 위임·아부 점수 균형, 5~10분 목표 시간 검증

## Phase 5 — 첫 출시 확장 (15일·20문제·20~30분)
- 문제 20개, 김 과장 대사 50개, 랜덤 이벤트 15개, 선배 2명, 엔딩 4~5종
- 추가 업무·일정 협상, 분야별 랭킹(골든 키보드/코드/넥타이/슬리퍼), 외부 랭킹 설계

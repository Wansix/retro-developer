# 《옛날 개발자》 게임 기획서

> 코딩은 입문 난이도, 직장생활은 하드코어.

**부제** — 퇴근하고 싶다  
**장르** — 실제 Python 코딩을 중심으로 한 싱글플레이 직장 생존 시뮬레이션  
**대상** — 코딩을 처음 해 보는 사람과 개발자 직장 풍자를 즐기는 사람  
**플랫폼 제안** — PC 브라우저, 키보드 입력 기준

이전 대화의 덱빌딩 제거 결정과 최신 DEMO 0.3을 바탕으로 작성했다. **10일·6문제·5~10분**은 체험판과 첫 구현 범위의 기준이고, **15일·20문제·20~30분**은 첫 출시 목표다. 문서에서 **구현 제안**으로 표시한 세부 규칙은 플레이테스트에서 조정한다.

## 1. 설정과 플레이 목표

2026년 오후 5시 58분. AI 코딩 에이전트는 퇴근 직전까지 파일 수정, 테스트 실행, 브라우저 확인을 차례로 승인해 달라고 한다. 신입 개발자가 “아니 그냥 내가 하는 게 빠르겠다!”를 누르자, 에이전트는 2006년 3월 미래소프트™로 그를 볼낸다. 돌아오려면 AI 코딩 지원 없이 납기 안에 프로젝트를 완성해야 한다.

- **생존** — 첼력을 관리하면서 업무와 마감을 감당한다.
- **클리어** — 기한 안에 프로젝트를 완료하고 2026년으로 돌아간다.
- **경쟁** — 입사 동기 최 사원을 인사평가에서 앞서고 골든 키보드상을 노린다. 개발자판 발롱도르에 해당하는 회사 시상식이다.

카드, 덱, 드로우, 카드 보상은 제거한다. 코딩은 에디터에서 직접 하고, 커피나 위임 같은 직장 행동은 버튼으로 고른다. 회사는 일을 잘 끝낸 사람에게 더 많은 일을 배정한다. 같은 날 입사한 최 사원은 코드를 한 줄도 직접 해결하지 않고 인사평가에서 앞서갈 수 있다.

## 2. 하루 진행과 상태

1. **출근과 업무 배정.** 입사 일차, 마감, 남은 행동력, 첼력, 프로젝트 진행률, 인사평가를 보여준다. 김 과장이 업무를 설명한다.
2. **업무 처리.** 문제 설명과 시작 코드를 읽고 `main.py`에 작성한다. 실행 결과를 확인하고 수정한 뒤 제출한다. 힌트, 커피, 아부, 위임도 선택할 수 있다.
3. **반응과 다음 업무.** 검수를 통과하면 진행률이 오르고 다음 업무가 열린다. 김 과장은 “오! 벌써 끝났어? 그럼 이것도 해줘.”라며 바로 다음 일을 준다.
4. **일일 인사평가.** 나와 최 사원의 직접 해결 건수, 인사평가, 야근 횟수, 월급을 비교한다. 월급은 둘 다 월 180만 원이다.
5. **정시 퇴근 또는 야근.** 정시 퇴근은 날짜를 넘기고 첼력을 회복한다. 야근은 같은 날에 제한된 첼력으로 행동을 더 한다. 첼력 고갈, 납기 초과, 프로젝트 완료 시 결말을 판정한다.

### DEMO 0.3 기준 행동값

아래는 체험판 소스의 수치이며, 실제 Python을 넣는 첫 구현의 밸런스 출발점이다. 시작 첼력은 100, 하루 기본 행동력은 3이다. 첼력은 0~100으로 관리한다.

- **직접 해결** — 행동력 1, 첼력 −5, 인사평가 +35, 진행 +1건, 직접 해결 +1건. 제출 실패는 행동력 소모 없이 재시도한다.
- **박 대리 찬스** — 행동력 1로 현재 문제의 힌트를 확인한다.
- **커피** — 행동력 1, 첼력 +15.
- **과장님께 아부** — 행동력 1, 인사평가 +45. 업무 진행에는 영향이 없다.
- **동료에게 위임** — 행동력 2, 인사평가 +20, 진행 +1건. 직접 해결 건수에는 포함하지 않는다.
- **정시 퇴근** — 다음 날로 진행, 첼력 +20, 행동력 3으로 초기화. 체험판에서는 이때 최 사원 평가도 +65.
- **야근** — 같은 날 행동력 +2, 첼력 −25. 첼력이 25 이하면 선택할 수 없다.

**구현 제안** — 실행과 제출을 분리하고, 실행 및 실패한 제출은 공짜로 둔다. 성공한 제출과 위임만 해당 업무를 완료한다. 체험판에서 김 과장의 추가 업무는 다음 필수 미션을 바로 던지는 연출이다. 첫 구현도 고정된 6문제와 이 연출로 시작한다. 별도 추가 업무, 일정 협상, 야근으로 마감을 맞춘 뒤 다음 일정이 단축되는 이벤트는 첫 출시에서 검토한다.

## 3. 코딩 미션과 입문자 지원

처음에는 보이는 한 줄을 따라 친다. 이후 주석으로 표시한 빈칸을 채우고, 실행 결과를 보고 한 줄을 고치는 단계로 진행한다. 각 업무에는 요구사항, 주어진 값, 기대 결과, 시작 코드가 있다. 코드가 틀렸을 때는 김 과장 대사 옆에 오류 유형과 줄 번호, 다음에 확인할 부분을 보여준다.

### 첫 구현의 6개 미션

1. **Hello, World!** — `print("Hello, World!")`를 따라 쳐 문자열을 출력한다.
2. **사장님 월급 인상** — 3,000,000원이 담긴 `salary`에 100,000을 더해 3,100,000을 만든다. `+=`와 일반 덧셈 대입을 허용한다.
3. **신입 기본기 — 별 찍기** — 주어진 반복문에서 1개부터 5개까지 별을 한 줄씩 출력한다. 문자열 반복과 들여쓰기를 익힌다.
4. **쇼핑몰 할인 버그** — 가격을 10% 올리는 버그를 고쳐 10,000원이 9,000원이 되게 한다. 체험판은 기대 출력을 `9000`으로 보여준다. **구현 제안**은 주어진 Python 코드에서 나오는 `9000.0`을 올바른 숫자 결과로 채점하는 것이다.
5. **고객사 매출 합계** — 가격 리스트의 합계를 `total`에 저장한다. 예제 결과는 6,000이다.
6. **최종 검수 — 회원가입** — 나이가 19세 이상이면 `allowed`가 참이 되게 한다. 예제 20세와 함께 18세·19세 경계를 검증한다.

첫 출시에서는 조건·반복·리스트를 복습하고 문자열, 함수, 디버깅 문제로 확장한다. 어려운 문법을 한꺼번에 요구하는 문제보다 기존 코드를 읽고 수정하는 업무를 먼저 배치한다.

### 박 대리 찬스와 복붙 이벤트

- **박 대리** — 코딩이 막힌 신입에게 “다음에 커피 한 잔 사라”며 힌트를 준다. DEMO 0.3은 바로 정답 한 줄을 보여준다. **구현 제안**은 문제마다 ‘어디를 볼지 → 문법 예시 → 채워 넣을 코드 일부’ 순서로 공개하는 것이다. 요청할 때마다 사용 횟수를 기록하고 열린 힌트는 해당 문제를 푸는 동안 다시 읽을 수 있게 한다.
- **복붙 이벤트** — 에디터에 코드 붙여넣기나 텍스트 드롭을 시도하면 입력을 막고 적발 횟수를 기록한다. 첫 시도에는 “신입, 한 글자도 안 치고 코드를 완성했다고?”, 반복 시도에는 “자네 Ctrl+V 말고 다른 키는 없나?”, “혹시 미래에서 왔어?”가 나온다.
- **구현 제안** — 클립보드 내용은 읽거나 저장하지 않고 편집기에 전달된 입력 이벤트만 처리한다. 정상 타이핑, 한글 입력기, 실행 취소, 자동 들여쓰기는 유지한다. 적발 횟수는 엔딩 통계와 연출에 쓰며 첼력이나 점수를 깎지 않는다.

## 4. 인물과 연출

- **김 과장** — 업무 배정자이자 평가자. 요구사항은 모호하고, 결과가 잘 나오면 동기 업무까지 맡긴다. 2026년의 플레이어가 AI에게 하던 “그냥 알아서 해줘”가 2006년에는 상사의 업무 지시로 돌아온다. 오류가 나면 “빨간 글씨 뜨는데? 잘되고 있는 거야?”, 정시 퇴근 다음 날에는 “어제 무슨 일 있었어? 왜 그렇게 일찍 갔어?”라고 한다.
- **최 사원** — 유일한 경쟁 동기. 코딩은 약하지만 적극적인 태도와 보고로 평가를 얻는다. 체험판 비교표에서 직접 해결과 야근은 각각 0이고, 정시 퇴근으로 다음 날이 될 때마다 평가가 오른다. **구현 제안**은 당일 성과 비교에 최 사원이 받은 점수의 이유를 한 줄로 보여주는 것이다.
- **박 대리** — 신입이 알아들을 만한 말로 코드의 다음 단계를 알려주는 선배. 첫 출시에서 도움을 주는 선배를 두 명으로 확장하는 목표가 있다.
- **AI 코딩 에이전트** — 승인 요청으로 도입부를 끌고 가고, 귀환 직후 조직 효율화 메일 소식을 전한다.

화면은 회녹색과 베이지 계열의 레트로 사무실과 초록 글씨 터미널을 쓴다. 상단에 상태, 업무 영역에 김 과장과 문제 설명, 가장 큰 영역에 코드 에디터와 실행 결과를 둔다. 일일 평가와 엔딩에서 같은 비교 항목을 보여줘 플레이 방식에 따른 결과를 읽기 쉽게 한다.

## 5. 엔딩과 시상식

체험판의 엔딩 판정 순서를 따른다. 10일 차까지 6건을 모두 완료하고 첼력이 남아 있으면 귀환한다. 직접 해결과 위임 모두 프로젝트 완료 건수에 포함한다.

1. **병원으로 출근** — 첼력 0. 최종 업무를 끝낸 행동에서 첼력이 0이 되어도 이 엔딩을 우선한다.
2. **영원한 신입** — 업무가 남은 채 10일 차를 넘긴다.
3. **차기 김 과장** — 귀환 조건 충족, 직접 해결 0건. 인사평가 순위와 관계없이 이 이야기가 우선한다.
4. **골든 키보드 수상** — 귀환 조건 충족, 직접 해결 1건 이상, 인사평가가 최 사원보다 높다.
5. **평범한 개발자** — 귀환 조건 충족, 직접 해결 1건 이상, 인사평가가 최 사원과 같거나 낮다.

**구현 제안** — 결과 화면에 귀환 여부, 엔딩, 인사평가 순위, 수상 여부를 각각 기록한다. 체험판의 엔딩 우선순위를 유지하면서도 직접 해결 0건으로 최 사원보다 높은 점수를 얻으면 ‘차기 김 과장’ 엔딩과 골든 키보드상을 함께 보여줄 수 있다. 동점일 때는 최 사원을 앞선 것으로 계산하지 않는다. 복붙 적발, 힌트 사용, 위임, 아부, 야근, 남은 첼력도 회차 결과에 남긴다.

## 6. 랭킹과 재도전

첫 구현에서 회사 내 순위는 나와 최 사원 두 명으로 구성한다. **구현 제안**은 완료 회차를 기기에 저장해 개인 최고 기록을 보여주는 것이다. 외부 유저 랭킹은 출시 목표이며 DEMO 0.3에는 없다. 외부 랭킹은 프로젝트 클리어를 등록 조건으로 삼고, 동일한 문제 구성과 규칙 버전끼리 비교하는 방안을 제안한다.

- **골든 키보드** — 종합 인사평가. 직접 해결로 얻는 기술 성과와 아부·위임으로 얻는 회사 점수가 모두 영향을 준다.
- **골든 코드** — 코딩 성과. 직접 통과한 미션 수를 우선 지표로 검토한다.
- **골든 넥타이** — 처세 성과. 직접 해결 0건으로 클리어한 회차의 인사평가를 비교하는 안을 검토한다.
- **골든 슬리퍼** — 워라밸. 야근이 적고 남은 첼력이 높은 클리어 회차를 우선하는 안을 검토한다.

첫 회차는 힌트로 코딩을 배우고, 다음 회차는 직접 해결을 늘려 최 사원에게 도전한다. 위임과 아부만으로 귀환하고 수상까지 노리는 회차도 가능하다. 분야별 동점 처리, 공개 랭킹 검증, 시즌·주간 챌린지는 출시 단계에서 규칙을 확정한다.

## 7. MVP와 첫 출시 범위

### 첫 구현 MVP — 10일, 6문제, 5~10분 목표

- 승인 반복 인트로, 시간 이동, 레트로 사무실, 업무 화면, 인사평가, 엔딩, 재시작.
- 실제 Python 실행과 채점, 기본 오류 안내, 할인 버그 수정 미션, 박 대리 힌트, 복붙 대사.
- 김 과장, 최 사원, 하루 행동력·첼력·프로젝트·평가 관리, 5개 엔딩, 회차 결과 비교.
- 고정 미션 순서로 입문 흐름을 확인한다. 개인 최고 기록은 브라우저 저장으로 시작하는 안을 적용할 수 있다.

### 첫 출시 목표 — 15일, 20~30분

- 실제 Python 문제 20개, 김 과장 상황별 대사 50개, 랜덤 직장 이벤트 15개.
- 경쟁 동기 1명, 도움을 주는 선배 2명, 엔딩 4~5종.
- 랜덤 사건과 여러 번의 회차에서 다른 결과가 나오는 구조를 도입한다. 추가 업무와 일정 협상은 기본 코딩 흐름을 검증한 뒤 확장하고, 분야별 외부 랭킹은 공개 기록의 검증 방식까지 설계한다.

### MVP 완료 판정

- Python을 처음 접하는 사람이 첫 출력과 할인 버그 수정을 게임 안 안내로만 끝낼 수 있다.
- 실행하면 작성한 코드의 실제 출력이 나오고, 틀린 이유를 확인한 뒤 고쳐서 다시 제출할 수 있다. 같은 결과를 내는 올바른 풀이도 통과한다.
